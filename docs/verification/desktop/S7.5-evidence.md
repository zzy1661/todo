**这条是「已损坏」变体，不是「未验证的开发者」变体。** 两者在 macOS 上的处置方式完全不同：

| 变体 | 按钮 | 「右键 → 打开」能不能放行 |
| --- | --- | --- |
| 未验证的开发者（`无法验证开发者`） | 取消 / 打开 | **能**（这是交付说明写的那条路） |
| 已损坏（本次实测） | 移到废纸篓 / 取消 | **不适用**——系统认定文件损坏，右键菜单里没有可放行的「打开」 |

所以：**交付说明里「右键 → 打开」这一步，在这份产物上不成立**。原因见 3.2。

### 3.2 为什么会判「已损坏」

```console
$ codesign --verify --deep --strict "…/bundle/macos/日程待办.app"
…/日程待办.app: code has no resources but signature indicates they must be present
codesign_verify_exit=1

$ spctl --assess -vv "…/bundle/macos/日程待办.app"
…/日程待办.app: code has no resources but signature indicates they must be present
spctl_exit=1

$ ls "…/日程待办.app/Contents/"
Info.plist  MacOS  Resources        # ← 没有 _CodeSignature/

$ codesign -dvvv "…/日程待办.app"
CodeDirectory v=20400 size=48440 flags=0x20002(adhoc,linker-signed) hashes=1510+0 location=embedded
Signature=adhoc
Info.plist=not bound
TeamIdentifier=not set
Sealed Resources=none
Internal requirements=none
```

读法：`flags=adhoc,linker-signed` = 这个签名是 Rust 链接器给可执行文件盖的（arm64 强制要求），
**不是 `codesign` 给整个 bundle 签的**——`Info.plist=not bound`、`Sealed Resources=none`、没有 `_CodeSignature/`。
Gatekeeper 看到一个「有签名但封条对不上」的 bundle，就按「已损坏」处理，而不是按「未签名」处理。
这也解释了为什么上一轮 `spctl --assess` 的 `rejected` 不只是「没公证」那么简单。

$ xattr -dr com.apple.quarantine "$GK/日程待办.app"

## 5. 为什么「点一下 / 按一下」全都做不到（可复现的失败动作）

屏幕录制授权只解决「看」，不解决「动」。下面是本轮**实际执行过**的失败动作，不是推断：

```console
# 1) 发按键
$ osascript -e 'tell application "System Events" to keystroke "a"'
execution error: "System Events"遇到一个错误："osascript"不允许发送按键。 (-1002)

# 2) 合成点击（AX 路线）
$ osascript -e 'tell application "System Events" to click at {500,500}'
execution error: "System Events"遇到一个错误："osascript"不允许辅助访问。 (-25211)

# 3) 直接 CGI 层合成点击（绕开 System Events）
$ swift /tmp/click.swift 273.5 257.5    # CGWarpMouseCursorPosition + CGEvent .leftMouseDown/.leftMouseUp @ .cghidEventTap
posted click at (273.5, 257.5)
$ # 截图对比：侧边栏「每日工作法」只出现了 hover 高亮，模块没有切换 → 光标动了，点击没送到

# 4) 按 PID 投递点击（再试一层）
$ swift /tmp/click2.swift 273.5 257.5 73387   # CGEvent.postToPid
posted to pid 73387
$ # 截图对比：同上，视图未切换

# 5) 换一个 responsible app 再试（排除「只是 opencode 没授权」）
$ open /tmp/ax-probe.command        # 让 Terminal 跑同一个探针
$ cat /tmp/ax-probe.txt
PROBE tcc.accessibility = false
PROBE tcc.screen-recording = true
```

结论：**`AXIsProcessTrusted = false` 是硬门**——`CGEvent.post` 在无辅助功能授权时被系统静默丢弃（光标能移、事件不生效），
`System Events` 则直接回 `-1002 / -25211`。Terminal 也没有辅助功能，说明不是「换个宿主进程就能绕」。
`osascript -e 'tell application "System Events" to count processes'` 能返回 91，**只说明 System Events 这个 Apple-signed 进程自己活着**，
不代表客户端被允许做 UI scripting——这一条上一轮有被误读的风险，本轮用 1)、2) 的错误码把边界钉死了。

**要解锁需要人类做的一步**（当前链路的 responsible app 是 `Multica.app`，不是 Terminal）：

> 系统设置 → 隐私与安全性 → **辅助功能** → 勾选 **Multica**（本轮实测从 Terminal 启动也不行，Terminal 同样未授权）
