## 0. 文档定位与阅读指引

### 0.1 本文是什么

本文是 **macOS 版**的产品需求文档。四份附件描述的是 **Windows 上已验证的现成产品**，它们是**事实基线**，不是 macOS 版的需求文档。本文做三件事：

1. 把基线里**必须逐条保持的行为契约**写成带编号的需求与业务规则（§8 FR-、§9 BR-）。
2. 把基线里**属于 Windows 实现细节、不得进入 FR 的取值**单独收进 §10「macOS 适配点」（ADP-）。
3. 把**材料未定义、不能自行拍板**的口径全部收进 §15（OP-），并给出默认建议与影响面。

### 0.2 三类内容的判定标准（写作纪律）

| 类别 | 判定标准 | 落在哪一节 | 能不能改 |
| --- | --- | --- | --- |
| 行为契约 | 用户可观察到的结果；换平台后必须一致 | §8 FR- / §9 BR- | 不能改；改动等同需求变更 |

## 1. 一句话定义

在 macOS 上从零重建「日程待办 / Schedule Todo」：一个**本地优先**的桌面应用——数据默认只存本机、不联网也能完整使用；在此基础上提供**可选的 GitHub 登录与 Supabase 云同步**（未登录 / 无 key / 断网时行为与基线完全一致）。它提供日历、每日工作法、全部待办三个模块，**可观察行为与 Windows 基线逐条等价**，并以 macOS 原生产物（`.app` / `.dmg`）交付；Windows 侧交付「可构建 + CI 验证」能力。

## 2. 背景与问题

| 编号 | 问题 | 后果（不做会怎样） |

## 4. 用户角色与权限（U-）

| 编号 | 角色 | 描述 | 权限 |
| --- | --- | --- | --- |
| U-01 | 本机用户（本地身份，唯一角色） | 在自己的 macOS 上使用应用的人；**不登录也能使用全部本地功能** | 三个模块的全部功能；无角色分级、无审批、无共享 |
| U-02 | 已登录用户（可选身份，同一自然人的另一种状态） | 在 U-01 基础上通过 GitHub 登录，使数据在**自己的多台设备**间同步 | 本地功能不变；额外获得同步能力；**看不到他人的数据**（由云表 RLS `auth.uid() = user_id` 保证） |
| U-03 | 维护者（code agent / 开发者） | 按本文重建与验证实现的人 | 读写源码、构建、运行测试；不得改用户真实数据（BR-14 衍生纪律） |

**权限模型结论**：

- **没有角色分级、没有审批流、没有组织/团队维度**。唯一的状态差是「是否已登录」，且它**只影响能否同步，不影响能否使用**（BR-24）。
- 数据可见性由**服务端 RLS** 保证（`auth.uid() = user_id`），客户端不做权限判断分支、不出现"无权限页"。
- 由此 §12.3 的结论是：三个主模块不存在无权限态；同步侧只有"未登录 ⇒ 不同步"，不是"无权限"。

## 9. 业务规则（BR-）

> 本节是**不可协商**的行为契约。与 §10 冲突时以本节为准；与 Windows 实现取值冲突时以本节为准。

| 编号 | 规则 | 判定要点 | 关联 |
| --- | --- | --- | --- |
| BR-01 | **日期口径**：所有日期一律为 `YYYY-MM-DD` 字符串（本地时区语义），仅使用 dayjs 处理日期运算与格式化，不使用其他日期库，不把 `Date` 对象跨层传递 | 数据层、store、组件三处传参均为字符串 | INV-06 |

| BR-03 | **优先级**：`0 = 低`、`1 = 中`、`2 = 高`，数值越大越紧急；新建默认 `1`（中） | 取值为整数，不含其他枚举 | — |

### 11.3 指标口径

| 指标 | 定义 | 分子 | 分母 | 数据源 | 刷新 |
| --- | --- | --- | --- | --- | --- |
| 共 N 项 | 当前视图总条数（不含筛选影响） | — | — | 待办表 / localStorage | 操作即刷新 |
| 已完成 M 项 | 当前视图 `done = 1` 的条数 | `done = 1` 计数 | — | 同上 | 操作即刷新 |
| 完成率 X% | `round(M / N × 100)`；N = 0 时整项不显示 | M | N | 同上 | 操作即刷新 |

| 推送记录数（验收用） | `daily_picks` 表行数 | — | — | SQLite | 验收时人工执行 |
| 内容库条数 | 内容库数组长度 | — | — | 内容库源码 | 校验脚本 |

### 11.6 同步相关字段口径（v3 迁移新增）

| 字段 | 类型 | 默认 | 口径 / 约束 |
| --- | --- | --- | --- |
| `uuid` | 文本 | 迁移时幂等生成 | 全局唯一、非空；幂等（二次启动不重新生成）；作为跨设备身份键，**不用本地自增 `id`** 做同步主键 |

| 同步指标 | 定义 | 口径 |
| --- | --- | --- |
| 推送次数 | 一个防抖窗口内的实际请求数 | 窗口内多次变更应恒为 1（BR-26） |
| 变更条数 | payload 中实际携带的条目数 | 应等于窗口内被改动且未被后续覆盖的条目数 |
| 同步结果 | 成功 / 失败 / 跳过（未登录或无 key） | 「跳过」不是失败，不得计为异常 |
| 云端验证状态 | `PASS` / `FAIL` / `NOT-VERIFIED` | 无 key 期间恒为 `NOT-VERIFIED`（BR-32） |

## 附录 A · 确定性推送参考实现（用于 AC-24 比对）

以下为**行为契约级**参考实现，macOS 版可改变文件位置与写法，但**计算过程与结果必须逐字等价**。

```ts
// 稳定哈希（FNV-1a）
function hashCode(str: string): number {
  let h = 2166136261;
  for (let i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h = Math.imul(h, 16777619);
  }
  return Math.abs(h);
}

// 可复现伪随机（mulberry32）
function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

// 某日期的确定性全排列（Fisher-Yates）
function permutationFor(date: string, ids: string[]): string[] {
  const out = [...ids];
  const rand = mulberry32(hashCode(date));
  for (let i = out.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [out[i], out[j]] = [out[j], out[i]];
  }
  return out;
}
```

比对口径（QA 执行）：

1. 从内容库取出 65 个 `id`，保持**内容库数组原始顺序**作为输入（顺序不同则排列不同）。
2. 对抽样日期 `d` 计算 `permutationFor(d, ids)`。
3. 断言 `permutationFor(d, ids)[0]` 等于数据库中该日 `method_id`（当 `manual = 0`）。
4. 对 `manual = 1` 的日期，断言数据库中的 `method_id` 出现在 `permutationFor(d, ids)` 中，且其下标 = 首推下标 + 1（模 65）。

#### D.2.1 CFL-07 裁定依据

**冲突事实**（对 `methods.ts` 独立求值所得，非引用他人结论）：

| 项 | 实测 | 说明 |
| --- | --- | --- |
| 总条数 | 65 | 与材料一致 |
| `steps` 分布 | 3 条 × 6、4 条 × 55、5 条 × 3、7 条 × 1 | 合计 65；**观测区间 3–7，不存在 2 条条目** |
| 超限条目 | `gtd` 5 / `smart-goal` 5 / `5w2h` 7 / `rice-scoring` 5 | 共 4 条 |

**裁定逻辑**：

1. 本项目的等价对象是 **Windows 基线实际交付的那 65 条数据**，不是 SPEC 里那条内容创作规范。规范与交付物冲突时，以交付物为准。
2. SPEC 的「2–4 条」描述的是"新增方法时怎么写"，属于**写作建议**，不构成对既有数据的验收条件；把它当硬断言会在**正确数据上误报失败**（`check-cases.mjs` 直接红），导致 G2 冤判。
3. 因此断言改为 **`steps ≥ 2`**（防止空步骤），并记录真实分布作为回归基线；4 条超限条目在此基线下**恒为通过**。
4. 数据原样搬运，一条不改文案；不得为凑规范把这 4 条压到 4 条以内——那才是破坏行为等价。
5. 设计侧必须按真实数据评估卡片高度：`5w2h`（7 步）与 `rice-scoring`（正文总长最大）在 1100×720 窗口下必然超出可用高度，二者固定为「内部滚动 + 底部渐隐」路径的 E2E 夹具。

> 一句话：**`steps` 上「行为等价」的判定标准是数据，不是规范。** 规范可以留作后续新增内容的建议，但不能用来给既有数据判错。
